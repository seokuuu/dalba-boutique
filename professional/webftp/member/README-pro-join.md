## 🎯 축2 최종 아키텍처 확정 (260729, 고도몰 2차 답변 + 담당자 협의 반영)

### 한 줄 요약
**회원가입은 달바 일반가입으로 통합(개발 0). Pro 여부는 오직 회원등급 `프로페셔널` 로 판별.** 로그인 회원이 별도 신청(게시판)에 서류 업로드 → 관리자 승인 = 등급 부여.

> **서류 제출은 신규·기존 회원 모두 "게시판 하나"로 통일한다.** (신규도 사업자회원 가입/comCertification 안 씀 → 전부 일반가입 + 게시판 서류)
> 이유: 서류가 한 곳(게시판)에만 쌓여 **저장영역 분리 문제(회원상세 사업자정보 vs 게시판)가 원천 소멸**하고, 관리자 확인도 한 곳에서. (담당자 확정 260729)

### 핵심 결정: 게이트는 "회원등급" (회원구분 아님)
- pro 접근·가격·판별 = **회원등급 `gMemberInfo.groupNm == '프로페셔널'`** 단일 기준.
- **왜 회원구분(개인/사업자)이 아니라 등급인가:**
  1. **이미 다른 사업자 회원이 존재** → 회원구분=사업자로 게이트하면 pro와 무관한 사업자들도 접근 열림 ❌ (결정타)
  2. 제휴가(할인)가 **등급 기준** 기능 → pro는 어차피 제휴 등급 슬롯을 씀 (등급은 1인 1개, 중첩 불가)
  3. 회원구분(`memberFl`)은 로그인 전역 객체 `gMemberInfo`에 **없음** → 전역 게이트 불가. 반면 등급은 `gMemberInfo.groupNm`으로 **확실히 전역 읽힘**(마이페이지 위젯에서 확인).

### 전체 흐름 (신규·기존 동일)
```
1. 회원가입 = 달바 일반 회원가입 그대로 (누구나 일반회원, 커스텀 0)
2. PRO 신청 = 로그인 후 별도 신청 게시판에 사업자/디자이너 등록증 업로드
              (비밀글 + 파일첨부, 유형=사업자원장/디자이너 선택 + 해당 서류)
3. 승인     = 관리자가 서류 확인 → "프로페셔널" 등급 부여 (+ SMS/알림톡 네이티브)
4. 접근     = pro 페이지에서 gMemberInfo.groupNm == '프로페셔널' 게이트
5. 제품/가격 = 상품·카테고리 등급 접근제한 + 등급 제휴가 (전부 고도몰 네이티브)
```

### 코드 사실 (검증됨)
- 등급 읽기: `gMemberInfo.groupNm`(등급명) / `gMemberInfo.groupSno`(등급번호) — `_member_summary.html` 위젯에서 확인.
- 로그인 판별: `gd_is_login()` / `checkLogin != 'guest'`.
- 회원구분: `memberFl`(personal/business) — 가입폼엔 있으나 `gMemberInfo` 전역엔 없음 → **게이트에 못 씀.**
- 게이트 적용 페이지: index / product / store / articles. **pro.html 제외**(로그인·안내 페이지).
- 게이트 판별은 **등급명 문자열 `'프로페셔널'`** 기준(번호 불필요). 단 등급명 변경 시 깨지므로 "이름 고정" 운영 필수(상수화).

### 게이트 코드 골격 (pro 페이지 상단)
```
<!--{ ? !gd_is_login() }-->            → pro.html(로그인)로 redirect
<!--{ : gMemberInfo.groupNm != '프로페셔널' }-->  → 안내로 redirect
<!--{ / }-->                            → 정상 노출
```

### 개발 범위
- ✅ **로그인** = 완료 (`professional/pro.html` + `js/professional/pro.js` + crypto-js, login.php secretKey→AES→login_ps.php)
- ⬜ **PRO 신청 게시판** — 서류 업로드(비밀글·파일첨부). store/articles 게시판 패턴 재사용
- ⬜ **pro 페이지 등급 게이트** — 위 골격, index/product/store/articles 상단
- ⬜ **관리자 세팅(개발 아님)** — "프로페셔널" 등급 생성 / 등급별 상품노출·제휴가(등급 할인율) / 승인 SMS·알림톡
- ❌ **불필요** — 커스텀 회원가입 플로우, comCertification 스킨 이식, 개인→사업자 전환, 5단계 가입 스킨

### 미결/유의
- **사업자번호 중복확인**: 게시판은 네이티브 중복체크 없음 → (A) 승인 시 관리자 수동확인(추천) / (B) 게시판 커스텀 중복검색(선택).
- **서류 보관 위치**: 게시판(회원상세 사업자정보와 별개). 승인이 수동이라 실무상 무방.
- `gMemberInfo`가 pro 스킨 페이지에서도 채워지는지 = **업로드 후 실테스트 1회 확인** (마이페이지 외 페이지 전역 여부).
- 등급명 "프로페셔널" 고정 — 관리자 리네임 시 게이트 깨짐 공유 필요.

### 고도몰 2차 답변 근거 (260729)
- 페이지 접근제한 네이티브 ❌ / 상품·카테고리 등급제한 ✅ → 페이지 게이트는 스킨에서 등급 체크로 자체 구현.
- 제휴가 = 등급 기준 완전 지원(상품별 등급가 / 상품 혜택관리 / **등급 자체 할인율**).
- 개인→사업자 전환·서류수집 = 네이티브 ❌, 커스텀 필요 → **전환 안 하고 등급+게시판으로 우회.**
- (1차) 가입은 전원 일반등급으로 되고 사업자는 관리자가 등급 변경 / 본인인증 DI로 1인 1계정.

## 🔁 파일 업로드 결론 수정 (중요)

기존 dalba_pro.md §3 은 "파일업로드 = 100% 순수 신규 개발" 이라 했으나, **실제 소스 확인 결과 틀림.**

- **고도몰 기본 기능으로 파일첨부가 존재** → `admin/member/member_joinitem.php` (사업자정보 섹션):
  - `comCertification[use/require]` = **사업자등록증** 업로드 (사용/필수/용량 관리자 설정)
  - `comAddiCert[N][name/use/require]` = **추가 첨부 항목** (항목명 관리자 지정, 추가/삭제 가능)
    → **"디자이너 자격증" 을 comAddiCert 항목으로 관리자에서 생성 가능**
- 다만 현재 프론트 스킨 `_join_view_business.html` 에는 이 파일필드 **렌더링 마크업이 빠져있음**
  (상호/사업자번호/대표자명/업태/종목/주소만 렌더). → **고도몰 원본소스의 마크업을 스킨에 되살리는 수준**.

### ✅ 관리자 화면 확인 완료 (260729, 사용자 캡처)
- **회원 → 회원 가입 항목 관리 → 사업자 정보 섹션에 실재 확인**: 상호 / 사업자번호(중복가입 제한 옵션) / 대표자명 / 업태 / 종목 / 사업장 주소 / **사업자등록증(필수)** / **추가 첨부 항목명(필수)**.
  → `comCertification`(사업자등록증), `comAddiCert`(추가첨부=디자이너 자격증) **네이티브 확정.**
- **⭐ 관리자 확인 경로**: 회원 관리 → 해당 회원 **상세정보 → 사업자 정보/첨부 항목**에서 업로드 파일 **다운로드·확인**. (승인제면 확인 후 승인 → 디자이너 등급) — 별도 개발 0. 저장·표시 전부 고도몰 담당.
- **프론트 input name 규칙(필수 준수)**: `name="comCertification"` / `name="comAddiCert[0]"` — 임의 이름 쓰면 백엔드 미인식 + 관리자 화면 미표시.

### ⚠️ 미해결 결정 (타팀 인증/승인 정책 컨펌 항목)
- **사업자등록증·추가첨부는 `회원구분: 사업자회원` 에만 붙음** (개인회원엔 미노출). → Pro 유형 매핑:
  - 사업자(원장) → **사업자회원** → 사업자등록증 OK.
  - 디자이너 → 개인회원이면 파일필드 안 뜸 → 자격증 받으려면 **디자이너도 사업자회원 처리** or 정책 정리 필요.
- 관리자 설정 액션(사용자): 사업자등록증 "필수" on 확인 + 추가첨부항목명에 "디자이너 자격증" 입력 후 저장.
- (원본 `_join_view_business.html`은 파일필드 없음 확정 → **input type=file 마크업은 우리가 직접 작성**, name만 위 규칙 준수.)

## 개조 대상 3가지 (근거 = 실제 소스 라인)

### 1) 회원유형: 개인/사업자 → 사업자(원장)/디자이너
- `join.html` L22-41 `memberFl` 라디오(`personal`/`business`) + L104-113 토글 스크립트.
- Figma: 사업자(원장) vs 디자이너. `businessinfo.use == 'y'` 조건으로 사업자정보 블록 토글되는 구조 재사용.

### 2) 파일 업로드 (사업자등록증 / 디자이너 자격증)
- `join.html` L15 `<form ... method="post">` 에 **`enctype="multipart/form-data"` 추가** 필요 (현재 없음).
- `_join_view_business.html` 에 comCertification/comAddiCert **`<input type="file">` 렌더 추가** (원본소스 이식).
- 관리자: `member_joinitem.php` 에서 comCertification(사업자등록증) + comAddiCert(디자이너 자격증) **use/require 켜기**.

### 3) 3번째 필수 약관 "(필수) 살롱·헤어디자이너 거래 동의"
- `join_agreement.html`:
  - 필수 검증은 **`class="require"` 기반** (L243 `$(':checkbox.require').each(...)`).
  - 기존 필수: `termsAgree1`(이용약관, L51) / `termsAgree2`(개인정보, L64) 만 `class="require"`.
  - 추가 약관(termsAgree3/4/5)은 전부 `(선택)`.
  - → **거래동의 체크박스에 `class="require"` + name 부여** 하면 프론트 필수검증 자동 적용.
  - 약관 본문은 `service/agreement.php?code=` 패턴 재사용.
- **백엔드**: 이 동의 값을 회원 레코드에 저장해야 하는지(법적 요구)에 따라 컨트롤러 처리 필요/불필요 갈림 (법률자문 확인 중 — dalba_pro.md §8).
